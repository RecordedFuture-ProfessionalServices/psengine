The first few examples will only show the errors as they would appear without proper error handling, then we will show how to handle them.

#### Example 3: Understanding `ValidationError` on wrong fields

Another common error that you might see in PSEngine is the `ValidationError`. This can be generated from two locations:

1. A method call
2. A method return value.

The example below shows the case 1, where you are supplying a parameter that is incorrect.
The case 2 is more rare and you cannot do anything to solve it, since this comes from an error during validation of what is sent by the Recorded Future API to PSEngine and can either mean an issue in the Recorded Future API or a bug in PSEngine. In this scenario what you can do is raise a support ticket to Recorded Future with the code sample you have been running and the error.

The `LookupMgr.lookup` method expect as parameter of `entity_type` (the second one) a string that must be one of the entity types that is defined in PSEngine. In this example we are passing an invalid string of `an ip address`.

#### Example 4: Proper error handling

When writing code with PSEngine is always good to surround PSEngine calls with the related error. You can find which exception a method will raise in three ways:

1. Via the API Reference in the "Errors" section of each module. 
2. Via the API Reference in the  manger section, in each method there is a "Raises" table showing which exceptions will be raised.
3. Via the method docstring. In any editor you should be able to see the docstring of the method if you hover over the method. The docstring will show the exception that it will raise.

Generally speaking the exception names are very intuitive for example the `ClassicAlertMgr.fetch` method raises the `AlertFetchError`, the `LookuMgr.lookup` raises `EnrichmentLookupError`. The structure of the name is `<Functionality><Method>Error`. 

Every manager (except for `stix2`) will have some scenarios where it will raise a `ValidationError`.

Given the above considerations we can write a safe enrichment the following way:

```python

```

In this example we are first catching any potential `ValueError` from the `LookupMgr` initialization. If there is a missing token or a wrong token the print a message, along with the `ve` exception and interrupt the script.

If everything is correct we start the lookup of entities. In this example we purposefully shown the `lookup` of each entity instead of using the `lookup_bulk` to make the example clearer to understand.

The third entity that we need to enrich has two issues:
1. The type of the key is incorrect, `1` should be a string
2. The `entity_type` value is incorrect, it should be one of the supported `entity_type`. 

This will raise a `ValidationError` but we decide to skip any entity that is not enrichable. 

An error with the API or the response will raise a `EnrichmentLookupError` which we do not want to ignore, hence we print a message, the exception and exit with error code `2`. This error code is not needed but is useful to understand at what point the script failed.

Lastly, if the entity has been enriched, we print the details.
The output should be:

```
EnrichedIP: 8.8.8.8, Risk Score: 0, Last Seen: 2025-09-03 10:03:12
EnrichedDomain: example.com, Risk Score: 24, Last Seen: 2025-09-03 10:21:54


WARNING: The entity "1", or the entity_type "example" are wrong. I will ignore it.


EnrichedDomain: example2.com, Risk Score: 0, Last Seen: 2025-09-03 10:18:15
```

This way the script does not crash if some scenarios can be handled more gracefully.
